# 0024 — Verticales : une chaîne de delivery complète par avatar

Date : 2026-11-13

## Contexte
Certains clients (Invoicing.Plus d'abord) lancent la même infrastructure sur un autre avatar. Il faut refaire
toute la chaîne (étapes 0 à 9) sans toucher à la verticale principale.

## Décision
- Table `verticals` (nom, avatar, marché, concurrents, changements de promesse, notes, mécanisme, statut).
- Activation par client : `clients.verticals_enabled` (case « Verticales » sur la fiche client). Création côté agence uniquement.
- Les étapes d'une verticale vivent dans `delivery_steps` avec une clé suffixée `<étape>@<id verticale>` (ex. `s1c@vt_x`).
  La verticale principale garde les clés simples (`instr(step,'@')=0`). Pas de reconstruction de table.
- Le robot lit la clé telle quelle dans la file : aucune modification du prompt du déclencheur.
  Le brief ajoute une section « Verticale » et, en référence, l'étape 0 et le mécanisme de la verticale principale.
- À la validation, le livrable porte `deliverables.vertical_id` et un titre préfixé par le nom de la verticale.
- Côté client : les livrables publiés sont regroupés par verticale dans l'infrastructure (tout est visible, comme une delivery normale).
- Migration 0017.
