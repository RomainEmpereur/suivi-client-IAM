# 0027 — Module Prospects : rédactions par la tâche Claude planifiée

Date : 2026-11-14

## Contexte
La section 29 demande quatre documents rédigés par un modèle (analyse, plan, script du Loom, pitch R2). La décision 0009 écarte toute clé d'API Anthropic dans l'espace : les rédactions passent par la tâche Claude horaire.

## Décision
- Les demandes de rédaction rejoignent la file de delivery existante (`/api/robot/delivery/queue`) avec la clé d'étape `pr~<type>` et l'identifiant du prospect (`pr_…`) à la place de l'identifiant client. Brief, dépôt et échec utilisent les mêmes routes robot que le delivery.
- Le brief contient le prompt du document (`docs/prospects/prompts/`, embarqué par `scripts/embed-prospect-prompts.mjs`), les chiffres avec leur origine, le coût maximum calculé par le code et la qualification. Le dépôt est un bloc JSON, contrôlé (clés requises) puis enregistré en brouillon.
- Délai : une demande est traitée au prochain passage (entre 7 h et 21 h), pas en direct. Accepté par Romain (choix « Tâche Claude horaire »).
- Dérogation à la section 3 (périmètre client) : ces tables ne concernent aucun client ; tout le module est réservé à l'agence. Un prospect signé peut être relié à un client, sans aucune copie de données vers son onboarding.
- Tables : `prospects`, `prospect_figures` (origine trame / transcription / manuel ; la saisie prime), `prospect_calls`, `prospect_documents` (versionnés), `call_templates` (versionnés), `case_studies`. Migration 0022.
- Non fait : liaison Fathom et import GHL (facultatifs dans la section 29).
